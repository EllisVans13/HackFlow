# HackFlow

Работающая платформа студенческих хакатонов: **Flask + PostgreSQL + React/Vite + Tailwind + Lucide**. Интерфейс на русском, три темы, данные сохраняются на сервере.

## Простой локальный запуск без Docker и PostgreSQL

Скачайте **ветку hello**: [ZIP](https://github.com/EllisVans13/HackFlow/archive/refs/heads/hello.zip), распакуйте. Один раз установите [Python 3.12+](https://www.python.org/downloads/) и [Node.js 22 LTS+](https://nodejs.org/). Если они уже установлены, повторная установка не нужна.

**macOS:** дважды нажмите `START-MAC.command`. Если запуск файла недоступен, откройте терминал в папке проекта и выполните:

```bash
bash START-MAC.command
```

**Windows:** `START-WINDOWS.bat`. **Linux:** `python3 scripts/start_local.py`.

При первом запуске скрипт сам создаёт `.venv-local`, устанавливает Python/npm-зависимости, собирает React, применяет миграции SQLite и создаёт демонстрационные аккаунты. Нужен интернет; подготовка может занять несколько минут. Повторные запуски используют сохранённые зависимости и сборку, пока исходники не изменятся.

Браузер откроется автоматически: **http://localhost:8000**. В окне запуска напечатаны email и случайный пароль демоаккаунтов. Пароль сохраняется между запусками; придумывать или вводить его при установке не нужно. Капитан: `captain@hackflow.test`, организатор: `organizer@hackflow.test`, администратор: `admin@hackflow.test` при первоначальном заполнении демобазы.

**Окно запуска оставьте открытым.** Остановка — Ctrl+C. Пользователи, сообщения, файлы и другие локальные данные находятся в `.local-data/`; не удаляйте эту папку, если хотите их сохранить. Перезапуск не сбрасывает пароли и не дублирует демохакатоны. При изменении пароля внутри приложения используйте новый пароль аккаунта.

Этот режим привязан к `127.0.0.1`, использует SQLite и отдельный секрет сессии. Он не меняет `.env`, PostgreSQL и данные Docker. Для серверного размещения и параллельной работы нескольких процессов остаётся PostgreSQL. Если порт занят: `python3 scripts/start_local.py --port 8001`. Напоминания работают в фоновом потоке одного локального процесса.

Прежний Docker-launcher сохранён как `python3 scripts/start_docker.py`. Он по-прежнему требует запущенный Docker Desktop.

## Ручной запуск на Windows и macOS

Установите Docker Desktop, Python 3 и распакуйте проект. Откройте терминал **в корне проекта**.

```bash
python scripts/configure.py
docker compose up --build -d
```

На macOS команда Python может называться `python3`; на Windows — `py`.

Добавьте демоданные (один раз, в пустую базу):

```bash
docker compose exec app flask --app wsgi seed-demo --password "YOUR_LOCAL_PASSWORD"
```

Откройте **http://localhost:8000**. Нужен именно HTTP; для локального запуска `COOKIE_SECURE=false` уже задан конфигуратором.

Создайте первого администратора защищённой интерактивной командой:

```bash
docker compose exec app flask --app wsgi init-admin
```

Укажите `admin@hackflow.test`, ник и отдельный пароль (минимум 12 символов). Администраторы через веб-регистрацию не создаются.

### Демонстрационные аккаунты

Пароль всех четырёх аккаунтов — **тот, который передан команде seed-demo**. В приведённом примере: `YOUR_LOCAL_PASSWORD`.

| Аккаунт | Email | Роль |
|---|---|---|
| Участник | participant@hackflow.test | Допущен, ещё не состоит в команде |
| Капитан | captain@hackflow.test | Капитан «Код будущего» |
| Организатор | organizer@hackflow.test | Организатор IT Hack 2026 |
| Жюри | jury@hackflow.test | Принявший роль жюри IT Hack 2026 |
| Администратор | Заданный в init-admin | Управление пользователями |

Код вступления в демонстрационную команду: **HACKFLOW26**. Демодаты считаются от момента заполнения: начало вчера, сдача через 5 дней, окончание через 7 дней. Самостоятельная регистрация **не выдаёт допуск** к закрытому событию.

Используйте демоаккаунты в изолированном демо. Перед публичным запуском смените пароли или создайте реальные аккаунты и новую базу.

## Проверка сценариев

1. Войти участником, открыть «Моя команда», вступить по `HACKFLOW26`.
2. Открыть кейс, материал, отметить изученным; открыть расписание и ссылку на учебную запись.
3. Создать задачу и изменить её статус. Отправить сообщение в командный чат.
4. В другом браузере войти капитаном. Открыть «Сдача проекта», добавить название, описание, публичный GitHub, HTTPS-ссылку на продукт и PDF.
5. При желании загрузить ZIP исходников. Запустить чек-лист, проверить предупреждения, отправить итоговое решение.
6. Войти организатором → «Управление» → «Проекты». Открыть PDF и ссылки.
7. Подготовить **обезличенный текст** вручную, сохранить, назначить деможюри (ID 4 в исходной демобазе). Запустить CodeCheck.
8. Войти жюри, открыть назначенную работу, поставить оценки по всем критериям, оставить комментарий.
9. Организатор публикует результаты. Участник видит командный и личный рейтинг.
10. Капитан подаёт апелляцию. Организатор отвечает; при принятии может изменить оценку конкретного эксперта с обоснованием. Личные рейтинги обновляются.

## Локальная разработка без Docker

Нужны Python 3.12+, Node.js 22+, PostgreSQL 17. Создайте PostgreSQL-пользователя и базу, задайте `DATABASE_URL` в `.env` и выполните конфигуратор (либо заполните `.env.example` вручную).

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cd backend
flask --app wsgi db upgrade
flask --app wsgi seed-demo --password "YOUR_LOCAL_PASSWORD"
flask --app wsgi run --port 8000
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
cd backend
flask --app wsgi db upgrade
flask --app wsgi seed-demo --password "YOUR_LOCAL_PASSWORD"
flask --app wsgi run --port 8000
```

Во втором терминале из корня:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Vite проксирует `/api` на Flask: cookies и CSRF работают через один origin. В production Flask отдаёт собранный frontend сам. Gunicorn применяется в Linux-контейнере; на Windows локально используется Flask dev server.

Фоновые напоминания в отдельном терминале из backend:

```bash
python -m hackflow.worker
```

Однократный запуск: `flask --app wsgi reminders`. Compose запускает worker автоматически. Не запускайте несколько workers напоминаний одновременно.

## Тесты

```bash
pip install -r backend/requirements.txt
pytest -q
cd frontend
npm ci
npm run build
```

По умолчанию тесты используют отдельную временную SQLite-базу только как быстрый тестовый стенд. Для проверки настоящих ограничений PostgreSQL используйте **пустую выделенную тестовую базу**, не рабочую: тесты создают и удаляют таблицы.

```bash
# macOS/Linux
TEST_DATABASE_URL=postgresql+psycopg://user:password@localhost/hackflow_test pytest -q
```

```powershell
# Windows PowerShell
$env:TEST_DATABASE_URL="postgresql+psycopg://user:password@localhost/hackflow_test"
pytest -q
```

GitHub Actions настроен на PostgreSQL 17. Фактически выполненные проверки записаны в `docs/VALIDATION.md`.

## Публичное развёртывание

Нужен Linux VPS с Docker Compose, домен с A-записью на IP сервера и открытые 80/443.

1. Скопируйте проект на сервер; выполните `python3 scripts/configure.py`.
2. В `.env` задайте `SITE_DOMAIN=ваш-домен`, `PUBLIC_URL=https://ваш-домен`, `COOKIE_SECURE=true`, `CORS_ORIGINS=https://ваш-домен`.
3. Выполните `docker compose --profile production up --build -d`.
4. Создайте администратора, при необходимости заполните демобазу или импортируйте допуски через UI.
5. Откройте `https://ваш-домен/api/health`; ожидается `{"database":"postgresql","status":"ok"}`.
6. Для восстановления пароля настройте SMTP STARTTLS в `.env`, перезапустите контейнер app. Без SMTP доступно только восстановление через сервер: `docker compose exec app flask --app wsgi reset-password`.

Caddy получает TLS-сертификат и проксирует app. PostgreSQL и Redis не публикуются наружу. Вход в app напрямую доступен только на loopback сервера. Не используйте dev server для публичного запуска.

Резервное копирование PostgreSQL:

```bash
docker compose exec -T db pg_dump -U hackflow -d hackflow > hackflow-backup.sql
```

Отдельно сохраняйте том `upload_data` с PDF и ZIP. Команда `docker compose down` сохраняет данные; `down -v` удалит их. Миграции применяет одноразовый сервис migrate перед app.

## Обновление: самостоятельное участие и уровни

Участник регистрируется на мероприятие в каталоге без одобрения. Один аккаунт может участвовать в нескольких событиях, но только в одной команде каждого события. Создатель команды становится капитаном; после передачи капитанства он остаётся участником. Код команды копируется в её кабинете; приглашённый сначала регистрируется на хакатон.

Организатор и аккаунт с событийной ролью жюри не могут участвовать ни в одном хакатоне. Их профиль не содержит активности и уровня. Ранее выданные допуски сохраняются как регистрации, но не отменяют запреты сотрудников.

Опыт начисляется по подтверждённой администратором сложности: лёгкий 70 XP, средний 150 XP, сложный 240 XP. Только за завершённые мероприятия с опубликованными результатами. Начальный уровень 0; суммарные пороги: 0, 250, 700, 1400, 2500, 4000, 6000 XP. Оценка проекта из 100 хранится отдельно и не меняет XP.

После получения изменений пересоберите контейнеры (не удаляйте тома):

```bash
git pull
docker compose up --build -d
docker compose exec app flask --app wsgi seed-showcase --password 'YOUR_LOCAL_PASSWORD'
```

Миграцию применяет сервис migrate. `seed-showcase` добавляет два завершённых, два текущих, два предстоящих и один проверяемый демохакатон. Существующие записи и пароли не меняются, повторный запуск не дублирует демособытия. Даты рассчитываются при первом добавлении каждого события; повторный запуск не передвигает сроки уже созданных мероприятий.

Демоаккаунты: participant, captain, organizer, jury и builder @hackflow.test. У новых аккаунтов пароль, переданный seed; у существующих пароль сохраняется. Запуск через SQLite: `python3 scripts/start_local.py`; через Docker: `python3 scripts/start_docker.py`. Адрес обоих вариантов: http://localhost:8000. Сайт не публикуется, ChatGPT-вход не используется.

Проверка обновления: 23 теста на PostgreSQL, серверный рендеринг React и сборка Vite. Визуальная проверка в браузере и фактический Docker-запуск в среде разработки не выполнены; мобильные изменения проверены только на уровне CSS/сборки.

## Главный администратор

Для локальной демонстрации `seed-demo` / `seed-showcase` создаёт `admin@hackflow.test`, **только если в базе ещё нет администратора**. Пароль — переданный параметром `--password` (при запуске локальным скриптом `YOUR_LOCAL_PASSWORD`). Существующие административные аккаунты и пароли не меняются. Публичная регистрация никогда не выдаёт административные права.

Войти администратором → «Администрирование». Доступны поиск зарегистрированных пользователей по имени/email, фильтр статусов, смена роли «Участник / Организатор», блокировка, назначение организатора на конкретные хакатоны и снятие этих назначений. Жюри отображается отдельной событийной ролью. При снятии глобального организатора отзываются его организаторские назначения. Проверки выполняются на сервере; административные аккаунты нельзя понизить/заблокировать через таблицу. Все изменения пишутся в аудит.

Для уже установленного проекта:

```bash
docker compose up --build -d
docker compose exec app flask --app wsgi seed-showcase --password 'YOUR_LOCAL_PASSWORD'
```

Для личного административного аккаунта вместо демо используйте защищённый `flask --app wsgi init-admin` до заполнения демоданных. Если администратор уже существовал, используйте его прежние данные или восстановите пароль через серверную команду `flask --app wsgi reset-password`.


## Понятный опыт и приглашения капитана

Начальный уровень 0 при 0 XP. Уровень 1 — 250 XP, уровень 2 — 700 XP. Профиль показывает опыт отдельно по каждому мероприятию, сложность, прогресс и точный остаток до следующего уровня.

Капитан → «Моя команда» → **«Пригласить участников»**. Список содержит ники, аватары и уровни зарегистрированных на этот хакатон участников без команды. Поиск по нику; максимум 100 результатов. Email не раскрываются. Приглашение сохраняется в базе, создаёт уведомление и действует до трёх дней, но не дольше дедлайна команд. Получатель принимает/отклоняет его в уведомлениях или разделе команды. Принятие повторно проверяет регистрацию, роль, единственность команды и её размер; приглашение не резервирует место.

Обновление ветки и `docker compose up --build -d` применяют новую миграцию приглашений. Проверено: 28 тестов PostgreSQL, production-сборка и серверный рендеринг React. Браузерная проверка не проводилась.


## Сложность и одобрение хакатонов

Организатор выбирает сложность при создании. Новое мероприятие получает статус заявки «На рассмотрении»: видимо только своему организатору и администратору, регистрация закрыта. Администратор → «Администрирование» → «Заявки на создание хакатонов» → «Рассмотреть»: может заменить сложность, одобрить или отклонить и добавить комментарий. Подтверждённая сложность определяет награду: лёгкий — 70 XP, средний — 150 XP, сложный — 240 XP за завершённое участие с опубликованными результатами, независимо от оценки команды. Повторная публикация не добавляет XP второй раз.

Уровни начинаются с 0. Порог уровня 1 — 250 XP, уровня 2 — 700 XP, далее 1400 / 2500 / 4000 / 6000 XP. Это общий накопленный опыт, а не дополнительная цена перехода. Например, два средних хакатона дают 300 XP и уровень 1; три сложных — 720 XP и уровень 2.

Миграция сохраняет существующие мероприятия одобренными и назначает им лёгкую сложность, чтобы не закрыть доступ старым участникам. Новые демонстрационные мероприятия имеют разные сложности и уже одобрены как учебные данные. Для обновления достаточно пересборки Compose: миграции применяются сервисом migrate. Существующий опыт пересчитывается автоматически из результатов и сложностей; отдельно мигрировать или обнулять пользователей не нужно.

Проверено: 30 тестов PostgreSQL, серверный рендеринг React, production-сборка Vite; миграция применена поверх существующей схемы. Визуальная проверка в браузере не проводилась.

## Владелец платформы и роли

Главный администратор отличается от обычного администратора флагом владения. Миграция назначает владельцем существующий административный аккаунт `admin@hackflow.test`; пароль не меняет. У новых демобаз этот аккаунт создаётся владельцем. Главный администратор остаётся с ролью admin, но получает исключительную кнопку «Передать владение». Передать можно только другому активному администратору, после подтверждения прежний владелец остаётся обычным администратором. Уникальный индекс PostgreSQL запрещает несколько владельцев; ограничение базы запрещает блокировку или понижение роли владельца.

Администраторы могут назначать роли участника, организатора, жюри и администратора, блокировать пользователей и выдавать организаторские/судейские права на конкретные хакатоны. Они не могут изменять права владельца или самостоятельно захватить владение. Изменение своих прав через таблицу отключено; передача владения выполняется отдельной операцией и сохраняется в аудите.

Организатор → «Участники и жюри» → «Назначить жюри»: указать email зарегистрированного пользователя. Назначение действует только на своё мероприятие; участник команды не может одновременно получить доступ жюри. Сохраняется и прежний сценарий одноразового приглашения. Для проверки конкретного проекта организатор дополнительно назначает работу этому жюри; назначение роли не раскрывает все работы автоматически.

Обновление — `docker compose up --build -d` после получения изменений из ветки: сервис migrate применяет новую схему. Если `admin@hackflow.test` не существует, миграция не создаёт аккаунт и не выдаёт права другому пользователю по случайному выбору: используйте прежний защищённый init-admin/seed-showcase согласно состоянию базы.


Фиксированный пароль локального администратора не задаётся. Укажите собственный пароль через параметр seed или защищённую команду init-admin. Docker-launcher при заполнении новой базы запросит его скрытым вводом. Простой SQLite-launcher автоматически создаёт случайный пароль и показывает его в своём окне. Пароли уже существующих аккаунтов сохраняются.

Организатор также может снять жюри: «Участники и жюри» → «Убрать из жюри» → подтверждение. Доступ к работам этого события и назначения на проверки отзываются сразу, неиспользованные приглашения этого пользователя в жюри события аннулируются. Другие хакатоны не затрагиваются. Оценки и история сохраняются; незавершённые проверки нужно назначить другому судье. Операция фиксируется в аудите.

## Город команд

Откройте **«Город команд»** в боковом меню выбранного хакатона.

- Созданная команда получает участок; выбранный кейс даёт фундамент.
- После создания задач появляется здание. Число этажей рассчитывается по доле выполненных задач: от одного до пяти. Отмена выполнения может уменьшить здание.
- После сдачи проекта загораются окна и появляется флажок. Это статус сдачи, а не оценка жюри.
- Нажмите на здание, чтобы увидеть команду, состав, кейс и общий прогресс. Есть поиск, фильтры и режим списка. Синхронизация происходит раз в 15 секунд; можно обновить вручную.
- Капитан выбирает архитектуру своей команды: башня, лаборатория, А-фрейм или дом на дереве. Все четыре варианта выбираются по миниатюрам в карточке здания. Выбор сохраняется в базе.
- Участник без команды может отправить заявку в команду с открытым набором. Капитан принимает её в разделе «Моя команда».
- Демо проекта открывается в карточке только после публикации результатов **и** согласия капитана. Согласие можно отозвать. Ссылки GitHub, файлы сдачи, задачи и переписка в городской API не включаются.
- Жюри не получает доступ к городу до публикации результатов; организатор видит его в пределах своих прав.
- В новогодней теме на зданиях снег, на участках ёлки и тёплые фонари. Есть управление с клавиатуры и обычный список команд вместо карты.

При обновлении существующей установки нужна миграция `a14_team_city`. Launcher без Docker и Docker Compose применяют её автоматически. При ручном запуске: `cd backend`, затем `flask --app wsgi db upgrade` перед запуском сервера. Пользовательские данные и сдачи не сбрасываются.


### А-фрейм и дом на дереве

Новые дома выполнены как векторные миниатюры в стиле города. У А-фрейма по мере готовности появляются крыша, стеклянный фасад, крыльцо и дымоход; у дома на дереве — кабина, окна, переход и огоньки. Для этих типов пять уровней прогресса означают степень готовности и детализацию, а не буквальное число этажей. После сдачи включаются тёплые окна и флажок. В новогодней теме виден снег; в остальных темах зимние накладки скрыты.

Существующий выбор архитектуры не меняется автоматически. Капитан открывает «Город команд» → своё здание → «Архитектура», затем выбирает тип в списке или нажимает миниатюру. Дополнительная миграция не нужна: используется поле city_style из a14.


## Автоматические дипломы

После публикации официальных результатов каждый участник команд на 1, 2 и 3 местах получает личный диплом. Он появляется в **профиле → «Дипломы»** и в результатах выбранного хакатона. Доступны просмотр и скачивание PDF формата A4. Пустой блок без наград не показывается.

В диплом подставляются имя из профиля на момент выдачи, название команды и хакатона, место, организатор, дата и номер. Для призовых мест используются золотой, серебряный и бронзовый акценты. Кириллические шрифты включены в PDF; системные шрифты и внешние сервисы генерации не нужны. Дипломы демонстрационных мероприятий помечаются «Демо».

Повторная публикация не создаёт копии. Если после апелляции изменилось место, прежний документ становится недействительным, новый выдаётся автоматически. PDF доступен владельцу, организатору этого события и администратору. Страница по QR-коду доступна без входа и показывает реквизиты документа и его актуальность. Для проверки с других устройств в `.env` задайте `PUBLIC_URL` равным доступному адресу сайта; `localhost` подходит только для проверки на том же компьютере.

Миграция `a15_award_certificates` автоматически создаёт дипломы и за ранее завершённые хакатоны с опубликованными результатами. Launcher и Docker Compose применяют её при обновлении. При ручном запуске обновите зависимости `pip install -r backend/requirements.txt`, затем выполните `flask --app wsgi db upgrade` из `backend`. Пользователи, команды, задачи и результаты сохраняются.
