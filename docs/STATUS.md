# Статус реализации

Актуальная сверка ветки `main` с обязательными требованиями присланного кейса «Актион HackFlow» находится в **[CASE_REQUIREMENTS.md](CASE_REQUIREMENTS.md)**. Проверены код, серверные ограничения, наличие интерфейса, тесты и публичная HTTP-доступность; оставшиеся ограничения отмечены отдельно.

Основная инструкция и ссылка на публичный сайт: [README](../README.md). Результаты выполненных проверок: [VALIDATION.md](VALIDATION.md).

Ключевые незакрытые пункты: отдельный бан участника организатором; браузерная проверка обязательного сценария и мобильного интерфейса. Настройка фоновых напоминаний, постоянного хранения файлов и доступов демоаккаунтов на Render требует отдельного подтверждения. Возможности, доступные только администратору, не следует приписывать организатору.

Исходное ТЗ и более ранние описания не являются подтверждением того, что функция реализована в текущем коде.

Обновление менторов: отдельная роль, выбор капитаном, назначение организатором и чтение назначенного пространства реализованы в `feature/mentors-russian-learning`. Учебный трек расширен до 16 русскоязычных позиций; поддерживаются семь форматов §5.3.

## Peer Review и встречи

Новое оценивание: 80% жюри + 20% среднего трёх команд, итог из 100. Минимум четыре команды, анонимные текст/PDF, по три независимых рецензента, публикация после завершения обязательных проверок. Есть отдельный демосценарий из четырёх команд и публичные доступы всех ролей в README. Ограниченный демоадминистратор не управляет реальными данными. Встречи имеют сервис, дату, время, длительность и URL; реальные комнаты создаёт организатор в Zoom/Телемосте через ссылки формы.

Peer Review доступен только участникам конкретного хакатона; капитан отправляет оценку команды. Раздел, прямой frontend-маршрут и API закрыты всем сотрудникам. Ручное управление Peer Review удалено, распределение выполняется сервером при переводе мероприятия в статус «На проверке». Публичный итоговый рейтинг сохраняется для всех.
