# Публичная ссылка через Render

Ветка `hello` подготовлена к запуску через Render Blueprint. Домен покупать не требуется: Render выдаёт постоянный HTTPS-адрес вида `https://hackflow-xxxx.onrender.com`.

**В конфигурации указаны платные ресурсы:** веб-сервис Starter, PostgreSQL Basic и постоянный диск 1 GB для аватарок, PDF и ZIP. Перед подтверждением Render показывает стоимость. Сам файл `render.yaml` ничего не создаёт и не списывает деньги. Бесплатный веб-сервис Render не поддерживает постоянный диск; бесплатный PostgreSQL ограничен сроком действия.

## Создание сайта

1. Откройте [запуск ветки hello на Render](https://render.com/deploy?repo=https://github.com/EllisVans13/HackFlow/tree/hello).
2. Войдите в Render и подключите GitHub, если сервис этого попросит. Источник должен быть `EllisVans13/HackFlow`, ветка `hello`.
3. В поле `ADMIN_EMAIL` укажите email для первого администратора. Остальные пароли и секрет сессии Render генерирует автоматически.
4. Проверьте список ресурсов и стоимость, затем подтвердите создание Blueprint.
5. Дождитесь статуса **Live** у веб-сервиса `hackflow`. Его публичная ссылка будет в верхней части страницы сервиса. Откройте её с телефона или отправьте другому человеку.

Если открыть Blueprint через ссылку не получается: **Dashboard → New → Blueprint → репозиторий HackFlow → ветка hello**. Файл конфигурации — `render.yaml` в корне.

## Первый вход

В веб-сервисе откройте **Environment** и скопируйте значение `ADMIN_PASSWORD`. Входите с email из `ADMIN_EMAIL` и этим паролем. Не публикуйте значения паролей и `SECRET_KEY`.

По умолчанию `SEED_DEMO=true`: новая установка заполняется демонстрационными хакатонами. Пароль демоаккаунтов `participant@hackflow.test`, `captain@hackflow.test`, `organizer@hackflow.test`, `jury@hackflow.test` и `builder@hackflow.test` — значение `DEMO_PASSWORD` в Environment. Для пустой установки перед первым запуском задайте `SEED_DEMO=false`.

Это **новая серверная база**. Аккаунты, фотографии и данные из локального Docker или SQLite на Mac автоматически в неё не переносятся.

## Что настраивается автоматически

- PostgreSQL подключается через внутренний URL Render; адрес преобразуется в формат установленного драйвера psycopg.
- Схема базы обновляется перед запуском сервера. Первый администратор создаётся один раз; повторный запуск не меняет его пароль.
- Публичный адрес берётся из `RENDER_EXTERNAL_URL`, поэтому QR-коды дипломов сразу ведут на сервер. Для собственного домена можно явно задать `PUBLIC_URL` и `CORS_ORIGINS`.
- Сайт слушает `0.0.0.0:$PORT`. Используются один Gunicorn worker и четыре потока, а также отдельный процесс напоминаний. При завершении контейнера оба процесса останавливаются.
- Файлы сохраняются на постоянном диске `/app/data`, загрузки — в `/app/data/uploads`. PostgreSQL хранится в отдельном сервисе.

Секреты в `.env` с компьютера не нужны. После обновлений ветки `hello` Render может автоматически пересобирать сайт; базу и диск удалять для этого не нужно. Генерируемые значения `ADMIN_PASSWORD` и `DEMO_PASSWORD` используются при создании аккаунтов и не сбрасывают пароли существующих пользователей. Для восстановления есть штатная команда `flask --app wsgi reset-password` в Shell веб-сервиса.

Конфигурация рассчитана на один экземпляр веб-сервиса с постоянным диском. Для нескольких экземпляров потребуется общее файловое хранилище, Redis для лимитов и отдельный процесс напоминаний.

## Проверка и диагностика

По адресу `https://ваш-сайт.onrender.com/api/health` должен возвращаться статус `ok` и база `postgresql`.

Если развёртывание остановилось, откройте **Logs** веб-сервиса. В первую очередь проверьте, что PostgreSQL доступен, указан корректный `ADMIN_EMAIL`, диск подключён, а пароль администратора содержит минимум 12 символов. Пароли скрипт запуска не выводит в журналы.

Официальная документация: [Blueprint](https://render.com/docs/blueprint-spec), [запуск из Docker](https://render.com/docs/docker), [ограничения бесплатного тарифа](https://render.com/docs/free).
