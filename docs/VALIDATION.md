# Проверки

Проверки выполнялись в рабочей среде, Python 3.12, Node.js 24, PostgreSQL 17.12. Целевые Docker-образы: Python 3.12, Node.js 22, PostgreSQL 17.

- `npm ci` / `npm run build`: production-сборка Vite проходит.
- `pytest -q` на отдельном **PostgreSQL 17.12**: 21 тест проходит, включая изображения и учебную аналитику.
- Исходные 14 тестов на SQLite: проходят. В исходной версии SQLite использовалась только для тестов; новый локальный режим описан ниже.
- `flask db upgrade` и `flask db check`: три миграции применены на PostgreSQL, расхождений со схемой моделей нет.
- `node frontend/scripts/smoke.mjs` (из frontend): 25 вариантов страниц проходят серверный рендеринг React без ошибок; это не браузерный тест.
- Ограничение одной команды проверяется прямой вставкой дубликата в базу, не только HTTP-ответом.
- Анонимный ответ жюри проверяется на отсутствие названия команды, авторов, исходных ссылок, presentation и team_id.
- CodeCheck проверяется двумя реально загруженными ZIP, а не предзаполненным отчётом.

Сценарии тестов: самостоятельная регистрация без допуска, команда/задача/чат/обучение/сдача, чужая команда, права капитана, запрет удаления после старта, публикация оценки, личный рейтинг, апелляция с пересчётом, диапазоны баллов, дедлайн, неверный PDF, одноразовое приглашение/email, CSV, назначение организатора, сумма критериев, CodeCheck без исходников, сравнение реальных исходников, опасные URL, CSRF, неизменность сдачи, консультации/конфликт жюри, идемпотентные напоминания, Peer Review, одноразовое восстановление пароля.

**Не выполнено:** браузерная проверка визуального результата, реальные SMTP-письма (нет настроенного почтового сервиса), `docker compose up` (Docker daemon отсутствует), публикация Flask на внешнем VPS. Успешные модульные/интеграционные проверки не являются подтверждением этих пунктов.

- Векторный A4 PDF: именной документ, место, команда, хакатон, организатор, дата и номер, настоящий QR. DejaVu шрифты с кириллицей включены в репозиторий вместе с лицензией и встраиваются в документ. Используется ReportLab 4.4.5; внешние сервисы генерации не нужны. Демодипломы маркируются.
- Профиль и рейтинг показывают карточки собственных дипломов с просмотром и скачиванием; в рейтинге фильтр ограничен текущим событием. Палитры существующих тем сохранены.
- Семь новых серверных тестов проверяют выдачу каждому участнику команд 1–3 мест, отсутствие награды за 4 место, отсутствие копий, доступ к PDF, публичную проверку, HTML-экранирование, отзыв/перевыдачу через реальную апелляцию и длинные кириллические строки в одностраничных PDF. На SQLite проходят семь тестов дипломов и два теста launcher; ранее пройденные проверки приложения сохранены.
- Полный прогон: 52 теста проходят с PostgreSQL (включая два изолированных SQLite-теста launcher). Проверены применение a15 к PostgreSQL a14 с существующими результатами, обратное заполнение и отсутствие расхождений со схемой моделей. На SQLite проверены пустая база и копия существующей базы a14: после обновления неизменны 18 пользователей, 15 команд, 62 задачи, 32 сообщения и 6 личных результатов; автоматически создано 6 дипломов. ## Подготовка запуска на Render

- Добавлены render.yaml и backend/start_render.py. Blueprint указывает ветку hello, платные Web Starter/PostgreSQL Basic и постоянный диск 1 GB; реальные ресурсы в Render не создавались. Конфигурация проверена по официальной JSON Schema Render.
- Entrypoint нормализует managed PostgreSQL URL для psycopg, получает PUBLIC_URL/CORS из адреса Render, применяет миграции и создаёт первого владельца. Повторный запуск не сбрасывает пароли и не дублирует демоданные. Один Gunicorn worker обслуживает четыре потока; процесс напоминаний запускается и завершается вместе с веб-сервером. Обычные локальные launcher и Docker CMD не изменены.
- Пять новых тестов проходят: варианты PostgreSQL URI, собственный домен/проверка конфигурации, динамический порт, начальная выдача владельца и повторный запуск с сохранением аккаунтов/результатов/дипломов.
- Прямой запуск entrypoint с Gunicorn и SQLite через HTTP: новый порт, CSRF-вход владельца, восемь демохакатонов, загрузка аватара, штатный SIGTERM и повторный запуск сохраняют аватар, прежний пароль и количества 18 пользователей/8 хакатонов/6 дипломов.
- Docker-образ собран с Node 22 и Python 3.12; проверены frontend и стартовый скрипт внутри образа, UID=10001. В данном окружении загрузки pip/npm проходили через временно смонтированный доверенный CA сетевого прокси; проверка TLS не отключалась, production Dockerfile и образ не содержат тестового CA.
- Docker end-to-end с отдельными PostgreSQL 16 и сетью: старт на PORT=10000, health=postgresql, CSRF-вход, восемь мероприятий, загрузка аватара от непривилегированного пользователя, личный PDF и публичная проверка диплома. Пересоздание веб-контейнера с тем же томом сохраняет аватар и пароль, SIGTERM завершает сервер штатно. Отдельно этот же сценарий прошёл с SQLite. Временные контейнеры, сеть и тестовый том удалены.
- Фактическая публикация, биллинг, HTTPS и подключение диска в аккаунте Render пока не проверялись: это следующий пользовательский шаг по docs/RENDER.md. PostgreSQL и файлы из локальной установки не переносятся автоматически.
