# Сверка с обязательными требованиями кейса «Актион HackFlow»

Дата: 15 ноября 2026 года. Основание — присланный документ «Актион HackFlow платформа отбора участников студенческих хакатонов.docx», кейс № 2 «HackFlow: цифровая среда для проведения студенческих хакатонов». Проверена ветка `main`, код на коммите `36c9d5e`. Обновление в `feature/mentors-russian-learning` добавляет отдельную роль ментора, полное чтение назначенного пространства и русскоязычную учебную подборку; строки ниже актуализированы для этой версии.

Документ рассматривается как спецификация для сравнения. Обязательные требования отделены от формулировок «дополнительно», «желательно» и «преимущество». Более поздние согласованные правила проекта — самостоятельная регистрация, запрет сотрудникам участвовать в командах — учитываются как изменения исходного сценария. Наличие функции в коде не означает, что она настроена или проверена на публичном стенде.

Обозначения: **есть** — найдена серверная реализация и соответствующие элементы интерфейса; **частично** — есть часть сценария с указанными ограничениями; **проверить** — результат зависит от развёртывания или ручной проверки.

## Дополнительные возможности и важные расхождения

- **Антиплагиат есть:** CodeCheck сравнивает загруженные ZIP проектов одного мероприятия, показывает сходство и фрагменты. Есть тест реального сравнения двух ZIP и тест отсутствия исходников. Это не поиск по интернету, не доказательство плагиата и не детектор ИИ. Демонстрационные отчёты не следует выдавать за реальные проверки.
- **Бан организатором отсутствует:** изменение `User.blocked` есть только в `admin_update`, который вызывает `require_admin`. UI блокировки находится в Admin. Организатору не дано ни глобального бана, ни отдельного бана/исключения на уровне хакатона. Сам присланный кейс не требует банов, но это запрошенное пользователем дополнительное поведение.
- **Назначение ролей администратора:** backend и UI поддерживают participant/organizer/jury/admin/mentor. Владелец и изменение собственных прав защищены отдельными проверками.
- **Уровни и результаты:** XP = официальный итоговый балл × коэффициент сложности 0,7/1,5/2,4 (максимум 70/150/240), старт с уровня 0, пороги 0/250/700/1400/2500/4000/6000. Оценки проектов по-прежнему из 100. Это отдельная функциональность сверх обязательного ядра.
- **Дипломы:** текущий main выдаёт документы призёрам 1–3 мест, а не сертификаты всем участникам. Публичная QR-проверка есть; общий официальный рейтинг опубликованных завершённых мероприятий доступен гостям через public results API и `/results/<id>`. Внутренний endpoint предварительного просмотра сохраняет авторизацию. Сертификатов всем участникам по-прежнему нет.
- **Напоминания Render:** `python -m hackflow.render_start` запускает миграции и веб-процесс; worker автоматически не запускается. Нужна отдельная настройка worker/планировщика. Её наличие на текущем стенде не подтверждено.
- **Загрузки Render:** PostgreSQL хранит записи, но PDF, ZIP и аватары лежат в файловой системе. После переноса только дампа БД или при отсутствии постоянного диска ссылки могут вести на отсутствующие файлы. Это необходимо проверить на публичном стенде.

## Что мешает заявить полное соответствие

1. Доступ ментора к назначенному рабочему пространству реализован; визуальная проверка этого сценария в браузере остаётся необходимой.
2. Для публичной демонстрации нужно подтвердить актуальные доступы трёх ролей, наполнение базы, сохранность файлов, реальные ссылки мероприятий и работающие фоновые напоминания.
3. Нужно пройти обязательный сценарий в браузере на компьютере и телефоне; HTTP-доступность и сборка этого не заменяют.
4. Запрошенный отдельно бан участника организатором в коде отсутствует.

## Дополнение: публичный архив

Раздел «Прошедшие хакатоны» доступен всем ролям и гостям. Опубликованные места/команды/проекты/баллы выдаются отдельным API с явным списком публичных полей. Неопубликованные рейтинги не раскрываются. У сотрудников скрыт участнический блок «Итоги хакатона».

## Дополнение: анализ кода для жюри

CodeCheck запускается при назначении жюри и обновляется при открытии работы, если изменился корпус. Жюри получает уведомление, статус, максимальное сходство файлов и нормализованные фрагменты, без идентификации авторов. Организатор и назначенное жюри могут повторить анализ. Нет ZIP/ошибка/частичная проверка/нет сравниваемых проектов различаются явно. Подробности и пределы — README, раздел проверки кода. Это дополнение к обязательному ядру кейса, не детектор плагиата по всему интернету.

Анонимные PDF доступны через проверяемый endpoint, исходные файлы/авторы не раскрываются. Публикация до всех оценок запрещена. Старые опубликованные результаты не переписываются. Есть четыре команды по одному человеку и 12 назначений; с тремя командами три независимых чужих рецензента невозможны. Отдельный эксперт оставляет рекомендации без официальных баллов. События расписания включают сервис/длительность/ссылку; Zoom и Телемост открываются из формы для ручного создания комнаты. Демодоступы всех ролей приведены в README.
